# Deploying to Render

This guide explains how to deploy the MakersLab Backend to Render.

## Prerequisites

1. A [Render account](https://render.com)
2. A MongoDB database (MongoDB Atlas recommended)
3. A GitHub/GitLab repository with your code

## Deployment Steps

### Option 1: Using the Blueprint (render.yaml)

1. **Push your code to GitHub/GitLab**
   ```bash
   git add .
   git commit -m "Add Render configuration"
   git push origin main
   ```
   
   Note: Make sure to commit your `yarn.lock` file for consistent dependencies.

2. **Create a New Blueprint on Render**
   - Go to [Render Dashboard](https://dashboard.render.com/)
   - Click "New +" → "Blueprint"
   - Connect your repository
   - Render will automatically detect the `render.yaml` file

3. **Configure Environment Variables**
   After creating the blueprint, you'll need to set the following environment variables in the Render dashboard:

   **Required:**
   - `MONGODB` - Your MongoDB connection string (e.g., from MongoDB Atlas)
   
   **Optional (based on your features):**
   - `GOOGLE_CLIENT_ID` - For Google OAuth
   - `GOOGLE_SECRET_ID` - For Google OAuth
   - `CLOUDINARY_URL` - For image uploads
   - `CLOUDINARY_API_SECRET` - For Cloudinary
   - `CLOUDINARY_API_KEY` - For Cloudinary
   - `MAIL_HOST`, `MAIL_USERNAME`, `MAIL_PASSWORD`, etc. - For email service
   - `SMTP2GO_*` - For SMTP2GO email service
   - `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_PHONE_NUMBER` - For Twilio
   - `REDIS_URL` - For Redis (if using rate limiting with Redis)
   - `OPENAI_API_KEY` - For OpenAI integration

   **Auto-generated:**
   - `JWT_SECRET` - Automatically generated by Render
   - `PORT` - Automatically set to 10000
   - `NODE_ENV` - Set to production

4. **Deploy**
   - Click "Apply" to deploy your service
   - Render will build and deploy your application

### Option 2: Manual Web Service Creation

1. Go to [Render Dashboard](https://dashboard.render.com/)
2. Click "New +" → "Web Service"
3. Connect your repository
4. Configure:
   - **Name:** makerslab-backend (or your preferred name)
   - **Region:** Oregon (or closest to your users)
   - **Branch:** main (or your default branch)
   - **Runtime:** Node
   - **Build Command:** `yarn install`
   - **Start Command:** `yarn start`
   - **Plan:** Free (or choose a paid plan)

5. Add all environment variables listed above

6. Click "Create Web Service"

## Setting up MongoDB Atlas (if needed)

1. Create a free account at [MongoDB Atlas](https://www.mongodb.com/cloud/atlas)
2. Create a new cluster (free tier available)
3. Create a database user
4. Whitelist Render's IP addresses (or use 0.0.0.0/0 for all IPs)
5. Get your connection string and add it as the `MONGODB` environment variable

## Post-Deployment

1. **Check Logs:** Monitor the deployment logs in the Render dashboard
2. **Test Your API:** Access your API at `https://your-service-name.onrender.com`
3. **Health Check:** The root endpoint `/` should return your public HTML page

## Important Notes

- **Free tier limitations:** 
  - Services spin down after 15 minutes of inactivity
  - First request after spin-down may take 30-60 seconds
  - Consider upgrading for production use

- **Database:** Make sure your MongoDB allows connections from Render's IPs

- **Environment Variables:** Never commit sensitive data to your repository

- **CORS:** Ensure your CORS settings allow requests from your frontend domain

## Troubleshooting

- **Build fails:** Check that all dependencies in package.json are correct
- **App crashes:** Review logs in Render dashboard
- **Can't connect to DB:** Verify MongoDB connection string and IP whitelist
- **502 errors:** Check that your app listens on the PORT environment variable

## Updating Your Deployment

Render automatically deploys when you push to your connected branch:

```bash
git add .
git commit -m "Your changes"
git push origin main
```
